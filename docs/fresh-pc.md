# Fresh-machine handoff

This project has not been accepted on a friend's Windows PC. A launcher already
installed on a machine does not establish a compatible version, an authorized
server/account, Java, Node or a model. The tested candidate is vanilla Java
Minecraft1.20.2 with Mineflayer4.39.0 on macOSarm64; modpacks/Bedrock/nativeNPCs
are outside this scope. Use the README's exact pinned install and checks.

An agent helping a new owner should first read AGENTS.md and README.md, verify
Node22.18–24/pnpm10.15.0, and run frozen install/check independently. Then identify
an authorized disposable loopback server/version and a legitimate permitted bot
connection. Never read launcher credentials, change existing server authentication,
use personal worlds, alter global Java/system volume or reuse private App data.
Obtain separate consent for new game/server/JDK/model downloads and the Minecraft
EULA. Offline tests require explicit isolated trust acceptance; they authenticate
no account. This CLI deliberately supports only that local test composition.

Create a new silent game profile before any graphical launch, verify its own
options.txt contains soundCategory_master:0.0, and leave personal profiles intact.
Mineflayer protocol clients and the nogui server require no audio settings.

Start the public App on loopback using its documented local workflow. Create an
original authored profile and explicitly select/create its memory in App; use
returned profile/memory IDs, never a display name as an identity. Verify scenario
native dialogue first. Select an actually installed Ollama model in App; review
its explicit token/context/deadline budgets and agree a bounded call count. No
model download or provider account is implied by this repository.

Then configure this bridge using the consenting player's exact serverUUID/name,
world alias, returned profile/memory IDs, loopback endpoint and fixed game version.
Start/stop using README commands, observe one private dialogue, and test recall
with the same memory after a manual reconnect. Keep user-reported events distinct
from observed game outcomes. A send call is not proof of human receipt/reading.
Do not promise a nativeNPC, autonomous game control, voice, multi-bot behavior or
Windows compatibility from this single-client text proof.

Record exact OS/runtime/game/dependency/model tuple, scenario versusLLM source,
effective budgets, native observed reply, restart/recall result and process cleanup
in owner-private evidence. Keep conversations, credentials, saved worlds and logs
out of Git. Independent source/native review and a fresh Windows run are separate
acceptance layers. No automated publication or deployment follows a successful run.
